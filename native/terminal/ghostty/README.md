# terminal-ghostty

Silk ownership around [libghostty-vt 1.0.0](https://lib.ghostty.org/vt/). Feed terminal
output bytes, encode input, collect protocol replies, resize or scroll the terminal, and capture
styled viewport cells or plain text.
The library has no dependency on the UI stack.

## Build

From the repository root, prepare the native library once per checkout:

```sh
python3 native/terminal/ghostty/scripts/prepare
silk test --manifest-path native/terminal/ghostty/silk.toml --root src/tests.silk
```

The preparation script verifies the official release's SHA-256. On macOS it extracts the
universal static library from Ghostty's XCFramework (Apple Silicon and Intel); no Zig is needed.
On Linux it builds the pinned release source with **Zig 0.17** (`ZIG` can name the executable).
Both paths need Python 3.12+ and curl. Linux's Zig build also downloads its upstream dependencies.
Headers come from the same release's SHA-pinned source archive in `silk.toml`.

Silk currently extracts tar archives, but not the Apple ZIP, so preparation writes the library
to the ignored `native/build/` directory. Re-run it after deleting build artifacts. These two
packages are listed in `layers.toml` as optional packages, outside the root workspace, because
they require this preparation and do not yet support Windows or browsers.

macOS builds need the same Xcode/LLVM setup as the other native packages. If the active developer
directory points to old Command Line Tools, set `DEVELOPER_DIR` to your Xcode installation.

## Use

Add a path dependency named `ghostty` on this package, then:

```silk
import ghostty.terminal { Terminal, GhosttyError }

effect fn example() -> () ! GhosttyError {
  let mut terminal = run Terminal.make(80, 24)
  terminal.write(b"Hello, \x1b[1;32mworld\x1b[0m!\r\n")
  let frame = run terminal.snapshot()
  let _cell = frame.cell(7, 0) // Option<Cell>: "w", green, bold
  run terminal.resize(100, 30, 10, 22)
  // frame still contains the original 80 x 24 screen.
}
```

`Terminal` owns the native handle and frees it on drop. Writes accept arbitrary byte chunks,
including partial UTF-8 and escape sequences. Parsing is best-effort, as in Ghostty itself;
`hasProcessingError()` exposes its sticky processing diagnostic. Native operation failures use
`GhosttyError.code`, preserving Ghostty's result codes (`-1` allocation failure, `-2` invalid value).

`snapshot()` uses Ghostty's render-state iterator, consumes terminal dirty state, and copies the
visible cells into an independent allocation. A snapshot survives later writes, resizing and
even destruction of its terminal. `cell(column, row)` bounds-checks zero-based coordinates and
returns an optional borrowed cell with the full UTF-8 grapheme, resolved RGB foreground and
background, SGR flags, and width (0 for a spacer, 1 or 2 otherwise). Colors are resolved through
the active palette but do not apply inverse, faint or invisible flags; that is the renderer's job.
Cursor coordinates and visibility and the default colors are also available on each snapshot.

`scroll(rows)` moves the viewport (negative is up); `scrollToBottom()` follows live output.
`reset()` clears screen, scrollback and modes while keeping the dimensions.
`plainText()` uses Ghostty's formatter to return the active screen and its scrollback without ANSI
styling, with trailing whitespace trimmed. It needs Silk's `Allocator` for the returned `String`.

## Input and replies

`encodeKey(key, modifiers, output)` writes a key press using the terminal's current modes,
including application-cursor mode. Keys use UI event names such as `Enter`, `ArrowUp`, `F1`,
or a character; modifier bits are Shift=1, Control=2, Alt=4, Meta=8 and CapsLock=16.
`encodePaste(text, output)` encodes clipboard text and honors bracketed-paste mode without
mutating the caller's text. Both return the number of bytes written to a caller-owned buffer;
send those bytes to the process, not to `Terminal.write`. Ordinary committed text can be sent
directly to the process as UTF-8.

`readReplies(output)` drains bytes generated by terminal queries such as cursor-position
reports. Call it after feeding process output, repeating until it returns zero, and send replies
back to the process. Replies are buffered up to 1 MiB; overflow or allocation failure is sticky
and returned as a `GhosttyError`. All encoder and callback state is owned by `Terminal`.

## Scope

This wraps the terminal core, viewport rendering data, plain formatter, key-press and paste
encoding, and protocol reply buffering. PTYs and subprocesses belong to the host. Mouse
encoding, full keyboard event reporting, selection, hyperlinks and image rendering are outside
this wrapper's current scope. Use handles on one thread at a time. Full snapshots favor simple
ownership over incremental-renderer performance.

See the [native terminal demo](../../../examples/terminal-demo) for a real shell host and renderer.
The integration tests exercise streaming ANSI/UTF-8, graphemes, styles, wide cells, ownership,
alternate screens, cursor visibility, invalid dimensions, resizing, scrolling, text export,
application-cursor mode, control keys, query replies and bracketed paste.
